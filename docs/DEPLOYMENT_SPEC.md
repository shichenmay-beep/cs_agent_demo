# 上线服务器与部署规格说明

按「工单消息每天约 40 条」量级估算，供选型参考。

---

## 一、请求量粗算（约 40 条工单/天）

| 动作 | 每工单约请求数 | 40 条/天合计 |
|------|----------------|--------------|
| 打开侧栏 | 1×优先级 + 1×翻译 + 1×总结 | 约 120 次调用后端 |
| 点击「生成回复」 | 1×建议回复 + 1×直译 | 约 40 次 |
| **合计** | — | **约 160 次/天** 请求到你的后端 |

后端再根据配置调用 OpenAI/OpenRouter，流量与计费在 LLM 侧，不占你服务器带宽。

---

## 二、仅部署 Node 后端（不用 RAG）

- **用途**：只跑 `backend/server.js`（优先级、翻译、总结、建议回复）。
- **建议配置**：
  - **CPU**：0.5～1 核即可。
  - **内存**：512MB 足够，256MB 在轻量下也可。
  - **带宽**：入站/出站均为小 JSON，可忽略；需保证能访问 OpenAI/OpenRouter。
- **形态**：单机 1 核 512MB、或 **Vercel / Railway / 云函数** 最低档即可满足。

---

## 三、同时跑 RAG 服务（Python + ChromaDB）

- **用途**：`rag/retriever.py` 作为 HTTP 服务（如 5001 端口），Node 通过 `RAG_SERVICE_URL` 调用。
- **建议配置**：
  - **RAG 服务**：0.5～1 核，512MB 内存（ChromaDB 持久化目录占少量磁盘）。
  - **Node 后端**：同上，512MB。
- **部署方式**：同一台机跑两个进程（Node 3000 + Python 5001），则建议 **1 核 1GB**；或 Node 与 RAG 分两台/两实例，各 0.5 核 512MB。

---

## 四、必须满足的条件

| 项 | 说明 |
|----|------|
| **HTTPS** | Zendesk 侧栏请求你的 `backend_url`，必须是 HTTPS（可用 Nginx/Caddy 反代或直接用云平台 HTTPS）。 |
| **公网可达** | Zendesk 从公网访问你的后端，需有公网 IP 或域名。 |
| **环境变量** | 生产环境设置 `OPENAI_API_KEY`（及可选 `OPENAI_API_BASE`、`OPENAI_MODEL`）；若用 RAG，再设 `RAG_SERVICE_URL`。 |

---

## 五、选型参考（40 条/天）

- **云函数 / Serverless**：如 Vercel、Railway、阿里云函数计算 等，按调用次数计费，约 160 次/天几乎可视为免费或极低成本。
- **轻量 VPS**：1 核 512MB～1GB（如腾讯云轻量、AWS Lightsail 最低档），月费约几十元级别即可。
- **不推荐**：高配多核、大内存不必需；数据库若只做配置可文件或环境变量，无需单独 DB 服务器。

---

## 六、小结

| 场景 | 建议最低配置 |
|------|----------------|
| 仅 Node 后端 | 0.5 核 512MB，或云函数/无服务器最低档 |
| Node + RAG 同机 | 1 核 1GB，HTTPS 反代 |
| 40 条工单/天 | 上述任一种均可，瓶颈在 LLM 接口限速与费用，不在本机性能 |

上线时把 **backend_url** 指到该服务的 HTTPS 地址即可。

---

## 七、国内部署说明

**后端部署在中国大陆时，有一个关键限制：**

| 问题 | 说明 |
|------|------|
| **OpenAI / OpenRouter 不可直连** | 当前后端默认调 OpenAI 或 OpenRouter，这些服务在境内无法直接访问（网络与合规原因），服务器从国内发起请求会失败或极不稳定。 |

**可选方案：**

1. **后端放在境外**（推荐）  
   - 把 Node（及可选 RAG）部署在 **香港、新加坡、日本或美国** 等，服务器可正常访问 OpenAI/OpenRouter。  
   - 客服在国内通过浏览器打开 Zendesk，浏览器请求的是 **Zendesk 的页面**，侧栏里 iframe 再请求你配置的 `backend_url`（你的境外服务器），由**客服浏览器直连你的后端**，一般可访问；若公司网络限制出境外网，需放行你后端域名或 IP。  

2. **后端在国内 + 用国产大模型**  
   - 服务器放在阿里云/腾讯云等国内机房，把 `server.js` 里调用 OpenAI 的地方改成**国产大模型 API**（如阿里通义、百度文心、字节豆包、Kimi 等），由后端请求国内可访问的 API，则不存在「出墙」问题。  
   - 需自行对接各家的 chat/embed 接口，请求与响应格式在代码里做适配。  

3. **后端在国内 + 代理访问 OpenAI**  
   - 服务器在国内，通过代理或 VPN 访问 OpenAI，实施和合规风险较高，一般不推荐。

**结论**：  
- 若继续用 **OpenAI / OpenRouter**：建议后端部署在**境外**（如香港轻量云、海外 Vercel/Railway）。  
- 若必须**服务器在国内**：建议改用**国产大模型 API**，并修改后端调用逻辑。
